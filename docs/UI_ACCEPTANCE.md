# 网页与移动端验收

本文件是可重复执行的验收步骤，不是已通过的浏览器测试证据。离线 Node 测试、构建成功不能替代真实操作、移动端检查或账户联调。

## 可选浏览器回归

应用依赖与 pnpm 锁文件保持不变。可在单独目录安装 Playwright，再运行本仓库的可选测试：

```sh
npm install --prefix /tmp/mai-browser-qa --no-save @playwright/test@1.58.2
/tmp/mai-browser-qa/node_modules/.bin/playwright install chromium
MAI_PLAYWRIGHT_PACKAGE=/tmp/mai-browser-qa/node_modules/@playwright/test \
MAI_QA_URL=http://127.0.0.1:5173 \
/tmp/mai-browser-qa/node_modules/.bin/playwright test --config tests/browser/playwright.config.mjs
```

先在另一个终端按 README 启动应用；Windows 可选择等效的隔离目录与环境变量设置。测试覆盖 1440、390 和 360 像素宽度，截图与失败追踪保存于被忽略的 `outputs/browser-regression`，不要自动作为公开材料提交。

此套浏览器回归拦截全部 `/api/mcp` 账户请求，使用明确的模拟失败，不读取令牌、不访问真实账户。即使全部通过，也不证明真实 MCP 流程通过。测试包括需求识别、数量、预算失败、额外餐品开关、优惠筛选、小票下载、加权分摊守恒、历史恢复、损坏历史拒绝、真实模式缺配置失败和水平溢出检查。

## 人工完整检查表

桌面至少 1440×1000；移动端至少 390×844、360×800，并在实际手机上复核触控、软键盘和下载行为。

- 输入完整餐品名、数量、人数、预算；检查解析提示与所选商品一致。输入含糊的“汉堡”时不得静默猜品种。
- 单品增减与总数 12 份上限；空需求不能计算，超界需求必须解释。
- 修改预算或需求后，旧结果明确标记且复制/下载不可用，重新计算才解锁。
- 一元预算保持原需求，并明确没有预算内方案；外送不能将餐品金额称为最终实付。
- 额外餐品开关两种状态都重新计算，检查额外数量、同需求基准与解释。
- 优惠关键词、渠道、到期过滤及零结果页面；过期和未开始优惠不能带入。
- 三人按 2:1:1 分摊，份额合计与小票一致；小票含演示声明。
- 保存后刷新、恢复、删除及确认清空；损坏或篡改历史不能白屏，不从本地存储恢复伪造的报价。
- 各导航页无横向溢出；按钮有名称，键盘可达，触控目标可操作，焦点可见。
- 真实页缺 Token、访问未授权或缺已核对映射时明确失败，不能显示演示结果。每次更改门店、需求、预算、套餐筛选都清除旧核价。

## 真实账户验收单独执行

仅在已授权环境、服务端令牌和经运行时 `tools/list`、实际返回核对过的配置存在时执行。不可把令牌、私有参数或账户返回粘贴到网页说明或公开日志。

1. 真实搜索并选定门店、到店自取，读取当前菜单与适用优惠。
2. 只选映射覆盖的少量商品和套餐，确认范围及未参与选项；当前优惠券仅展示，不自动叠加。
3. 输入同一需求，分别核对单点基准和所有保留候选的官方金额、额外餐品及预算。
4. 验证缺令牌、失效令牌、权限不足、限流、超时、Schema 变化、业务失败、查询部分失败、价格缺失和无预算内方案均不回退演示金额。
5. 记录脱敏结果及必要截图；不得把模拟 HTTP 返回或旧账户证据标为这次端到端成功。
