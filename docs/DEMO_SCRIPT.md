# 90 秒演示讲稿

录制前在页面上保留“演示数据”标识。画面中的价格随当前样例计算，不在讲稿中预写固定优惠数字；真实 MCP 未联调时，不把查看器或样例说成实时门店结果。

| 时间 | 操作 | 讲述 |
| --- | --- | --- |
| 0—12 秒 | 打开首页，指出项目名与来源标签 | “买套餐以前，我先想清楚自己要吃什么。麦麦刚刚好把原本的需求放在第一步，价格和优惠随后来算。” |
| 12—28 秒 | 选择两种餐品与数量，设置预算 | “比如这顿只想要这些。先设置预算，程序根据当前商品集合，把能够满足需求的购买组合逐一比较。” |
| 28—44 秒 | 展示只买所需餐品的结果，展开账单 | “这里能看到买了什么、付多少钱，以及节省额和哪个基准比较。预算不够会直接显示，不把不可行方案包装成推荐。” |
| 44—60 秒 | 打开允许额外餐品，再对比方案 | “如果我接受套餐多带一份餐品，就主动打开这个选项。多出来的东西会列出来。是否值得，仍由我决定。” |
| 60—72 秒 | 查看小票，展示分摊或保存记录 | “选好后生成清楚的小票。一起点餐可以分摊，分摊金额加起来与总额一致，结果也能留在本机历史里。” |
| 72—84 秒 | 打开真实 MCP 接入区域 / 展示 Skill | “项目还提供官方 MCP 的只读接入和 Agent Skill。它按运行时工具定义查询、核价，凭证留在服务端，所有输出保留来源。” |
| 84—90 秒 | 回到方案与需求 | “现在展示的是样例演示。我们的目标很具体：买到想吃的，算清付出的，刚刚好。” |

## 演示注意

先跑一遍所选案例，确认两种模式是否产生不同结果；相同结果也是有效结果，不人为制造优惠。如果展示 MCP，提前检查自己的凭证与联网条件，不录制 Token、手机号、地址或账户信息。无法完成真实调用时展示接入流程和明确的待验证状态即可。
